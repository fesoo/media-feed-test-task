# Разбор проекта

[Карта документации](README.md) · [Проверки](TESTING.md) · [План развития](ROADMAP.md)

## Оценка

Проект подходит для публикации как автономный frontend-прототип: данные и медиа включены, зависимости зафиксированы, сборка проходит. Реального backend и подтверждённой production-готовности нет.

Сильные стороны: разделение Query cache и UI store, ограниченное окно тяжёлых карточек, нативное воспроизведение, общие настройки, локальный прогресс, самостоятельный media adapter и возможность запуска без внешних сервисов после установки зависимостей.

## Границы демонстрации

- Каталог фиксирован: 45 записей, шесть разных беззвучных MP4. Нагрузку реального видеосервиса он не моделирует.
- Числовой cursor — смещение внутри локального списка; серверного курсора и ранжирования нет.
- Лайки не сохраняются между перезагрузками и устройствами; штатного моделирования отказа API нет.
- Атрибут preload и Network Information API не обеспечивают строгий бюджет трафика.
- Базовые ARIA-атрибуты и keyboard shortcuts не заменяют аудит доступности.
- Нет автоматических unit/component/E2E-тестов; выполненные проверки описаны отдельно в [TESTING.md](TESTING.md).
- Демо заменено собственными синтетическими градиентами; генератор включён в репозиторий. Лицензия проекта пока не выбрана.

## Что изменено при подготовке репозитория

Корневой README сокращён, технические материалы разнесены по `docs/`, реализованное поведение отделено от предложений. Уточнены preload, HLS fallback, метрики, viewed-policy и отсутствие аудио. Удалена дублирующая заметка о проверке архива.

Добавлены правила исключения локальных файлов, единые настройки отступов/переводов строк и CI для чистой установки и сборки. Диапазон Node.js в manifest и lock-файле согласован с установленным Vite. Демо заменено синтетическими градиентами с включённым генератором. Основной README оформлен на английском как take-home assignment для портфолио. Зависимости и прикладная логика не менялись.

Публикация исходников на GitHub и развёртывание сайта не выполнялись. Последующие исправления из таблицы стоит делать отдельными изменениями с проверкой соответствующих сценариев.
