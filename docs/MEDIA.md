# Медиа и производительность

[Карта документации](README.md) · [Production-план](ROADMAP.md)

## Демо-файлы

В [public/media](../public/media/) находятся шесть MP4 и шесть WebP-постеров. Каждый ролик: H.264, 360×640, 6 секунд, без аудиодорожки. Каталог из 45 записей повторно использует эти файлы.

Локальная статика позволяет запускать демо без внешнего CDN и CORS-настроек. Маленькие файлы не демонстрируют реальную нагрузку, ABR, переключение качества или работу CDN.

Для публичной версии исходные файлы заменены синтетическими анимированными градиентами, созданными специально для этого проекта. Палитры, seed и параметры кодирования находятся в [генераторе](../scripts/generate_demo_media.py); сторонние видео, фотографии и аудио не используются.

Пересоздание: `python3 scripts/generate_demo_media.py`. Нужны Python 3 и FFmpeg с libx264/libwebp; для запуска самого приложения они не требуются. Результат может отличаться побайтово между версиями FFmpeg.

## Нативный плеер и HLS

[useMediaSource](../src/hooks/useMediaSource.ts) выбирает источник:

```text
Нет hlsUrl             → MP4
Есть нативный HLS      → hlsUrl через video.src
Есть поддержка hls.js  → hls.js + Media Source Extensions
Иначе                 → MP4
```

В локальном каталоге `hlsUrl` не задан. HLS-ветки подготовлены в коде, но не проверены на реальном потоке.

MP4 fallback работает при отсутствии HLS/MSE-поддержки. Автоматического переключения на MP4 после ошибки уже выбранного HLS-источника нет. HLS fatal network/media errors вызывают `startLoad()` / `recoverMediaError()` без собственного лимита попыток; прочие fatal errors передаются карточке.

Для hls.js заданы `enableWorker`, `capLevelToPlayerSize`, `startLevel: -1`, `backBufferLength: 0`, `maxBufferHole: 0.5`. Целевой `maxBufferLength` зависит от роли: active — 12 секунд, next — 6, previous — 1. Это параметры HLS, а не точный контроль буфера MP4.

При смене соседней роли HLS instance сохраняется, его buffer length обновляется. При выходе из media window элемент размонтируется, HLS останавливается, отсоединяется и уничтожается. Смена роли на previous сама по себе не вызывает `stopLoad()`.

## Окно карточек

Полноценные карточки рендерятся в диапазоне `activeIndex ± 4`: максимум девять. Высоту остальной части списка сохраняют spacer-элементы. Источник подключён максимум к трём карточкам:

```text
previous | active | next
```

Остальные карточки окна показывают постер без `<video>`. Это ограничивает число элементов и декодеров, но не является переиспользуемым пулом плееров. Страницы метаданных остаются в Query cache.

`ResizeObserver` предусмотрен для пересчёта viewport и выравнивания scrollTop. Его подключение при первой загрузке требует исправления, см. [разбор проекта](PROJECT_REVIEW.md).

## Реальная стратегия preload

Профиль сети определяется по `saveData`, `effectiveType` и `downlink`:

| Условие | Профиль |
|---|---|
| saveData, slow-2g или 2g | `constrained` |
| 3g либо downlink < 2,5 Mbps | `moderate` |
| 4g либо downlink ≥ 2,5 Mbps | `fast` |
| Сведений нет | `unknown` |

Приоритет проверок соответствует порядку строк. Атрибут `preload` в VideoCard:

| Роль | fast / unknown | moderate / constrained |
|---|---|---|
| active | `auto` | `auto` |
| previous | `metadata` | `metadata` |
| next | `auto` | `metadata` |
| poster | `<video>` отсутствует | `<video>` отсутствует |

`preload` — подсказка браузеру, не гарантия количества загруженных байтов. При отсутствии Network Information API используется `unknown`, то есть для next — `auto`. Save Data не отключает источник next полностью. Динамического решения по скорости HLS-сегментов, памяти или длительности буфера пока нет.

## Ошибки и повтор

На уровне media element предусмотрены повторные `load()` через 400 и 800 мс, затем состояние ошибки с кнопкой. Эта ветка отличается от восстановления HLS. Требуется проверить взаимодействие retry с эффектом активации карточки: сброс fatal-состояния может повторно запустить цикл, см. [разбор проекта](PROJECT_REVIEW.md).

Постер остаётся доступен; автоматического пропуска ошибочного ролика нет. HLS-восстановление и повтор по кнопке требуют отдельных интеграционных тестов.

## Кэш и размер сборки

TanStack Query хранит метаданные, браузер — HTTP cache и media buffer, localStorage — настройки и ID. Полные видео вручную не сохраняются в localStorage или IndexedDB; Service Worker и гарантированного offline-режима нет.

`VideoCard` обёрнут в `React.memo`, прогресс обновляется локально примерно до 10 раз в секунду. Некоторые callback props создаются в MediaFeed заново, поэтому memo не гарантирует пропуск каждого лишнего рендера.

HLS-библиотека импортируется статически даже для MP4-демо. При проверке основной JS получился около 760 kB до gzip и вызвал предупреждение Vite о chunk > 500 kB. Динамическая загрузка hls.js — отдельная задача оптимизации; performance budgets и измерения на устройствах пока не подтверждены.
