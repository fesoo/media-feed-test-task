# Разработка

## Среда

- Node.js `22.16.0` из [.nvmrc](../.nvmrc) — версия для воспроизводимой локальной проверки и CI.
- Допустимый диапазон в [package.json](../package.json): `^20.19.0 || >=22.12.0`, как у установленного Vite.
- npm `10+`; поле `packageManager` указывает `npm@10.9.2`.

Если используете nvm:

```bash
nvm install
nvm use
```

## Установка и запуск

В корне проекта:

```bash
npm ci
npm run dev
```

`npm ci` устанавливает зависимости по lock-файлу. `node_modules/` и `dist/` не включаются в Git. Для установки нужен доступ к npm или заранее заполненный локальный кэш; после установки демо работает с локальными данными и медиа.

Приложение не требует `.env`, авторизации, базы данных или API-ключей.

| Команда | Назначение |
|---|---|
| `npm run dev` | Сервер разработки, порт 5173 |
| `npm run typecheck` | Проверка TypeScript через `tsc -b --pretty` |
| `npm run build` | Проверка TypeScript и сборка в `dist/` |
| `npm run preview` | Локальный просмотр `dist/`, порт 4173 |

Серверы настроены с `host: true`: для проверки с телефона можно открыть адрес компьютера в локальной сети. Для запуска только на своём компьютере:

```bash
npm run dev -- --host 127.0.0.1
npm run preview -- --host 127.0.0.1
```

При занятом порте Vite выберет следующий; `--strictPort` заставит команду завершиться ошибкой вместо смены порта. `preview` требует предварительной сборки.

## Где менять поведение

| Задача | Файл |
|---|---|
| Каталог, размер страницы, задержка API | [mockApi.ts](../src/lib/mockApi.ts) |
| Порог свайпа, wheel, окно карточек | [MediaFeed.tsx](../src/components/MediaFeed.tsx) |
| Воспроизведение, удержание, preload и retry | [VideoCard.tsx](../src/components/VideoCard.tsx) |
| HLS и буфер | [useMediaSource.ts](../src/hooks/useMediaSource.ts) |
| Сетевые профили | [useNetworkProfile.ts](../src/hooks/useNetworkProfile.ts) |
| Режим повторов и общие настройки | [feedStore.ts](../src/store/feedStore.ts) |
| Порты и параметры сборки | [vite.config.ts](../vite.config.ts) |
| Оформление | [styles.css](../src/styles.css) |

Синтетические демоматериалы пересоздаются командой `python3 scripts/generate_demo_media.py` (Python 3 и FFmpeg с libx264/libwebp). Для обычного запуска генерация не требуется.

Модели данных лежат в [types/feed.ts](../src/types/feed.ts). Путь к медиа задаётся в каталоге; новые файлы нужно поместить в `public/media/`.

## Локальные данные и диагностика

| Хранилище | Содержимое |
|---|---|
| `localStorage['media-feed:settings']` | Режим повторов, через Zustand persist |
| `localStorage['media-feed:viewed-video-ids']` | До 500 просмотренных ID |
| TanStack Query cache | Страницы ленты и оптимистичные лайки в памяти |
| `window.__FEED_METRICS__` | Последние 300 событий текущей страницы |

Для чистого сценария очистите только данные приложения в консоли браузера и перезагрузите страницу:

```js
localStorage.removeItem('media-feed:settings');
localStorage.removeItem('media-feed:viewed-video-ids');
location.reload();
```

Звук и активный индекс после перезагрузки сбрасываются. Лайки живут в памяти мокового API; реального сохранения на сервере нет.

## Типичные проблемы

- **`node` не найден или неподходящая версия:** выполните `nvm use` в текущем терминале.
- **Зависимости не совпадают с lock-файлом:** проверьте изменения `package.json` и `package-lock.json`; при намеренном обновлении зависимостей обновляйте оба файла.
- **Чёрный экран или ошибка медиа:** проверьте, что все файлы `public/media/` присутствуют и приложение открыто через Vite, а не напрямую как `file://`.
- **После включения звука тишина:** деморолики не содержат аудио. Состояние кнопки можно проверить визуально, звучание — только с другими файлами.
- **Клавиатурные команды не срабатывают:** переведите фокус внутрь ленты. Панель повторов находится вне контейнера с обработчиком клавиатуры.
- **Предупреждение о размере сборки:** HLS-библиотека включена в основной JS; это известное ограничение, см. [разбор проекта](PROJECT_REVIEW.md).

## Перед изменениями и отправкой кода

Сохраняйте разделение server state, UI state и состояния плеера, описанное в [архитектуре](ARCHITECTURE.md). После правок выполните `npm run build`, проверьте затронутые [ручные сценарии](TESTING.md#ручная-проверка) и обновите документацию. При изменении зависимостей включайте lock-файл в те же изменения.
